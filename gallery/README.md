# Gallery

Svelte app embedded in the MCP host (Claude Desktop, CoWork, …) as an MCP
Apps iframe. Built with Vite; assets are served by the Woof HTTP server at
`/gallery-static/`.

```
npm run dev      # local dev server
npm run build    # production build → ../src/woof/gallery/dist
npm test         # vitest
npm run lint     # eslint
```

## Localization

UI strings are localized with [Paraglide JS](https://inlang.com/m/gerre34r).
Supported locales: `en` (base), `en-GB`, `fr`, `de`, `es`, `zh` (Simplified),
`ja`.

- **Source of truth:** `messages/{locale}.json` (inlang message format).
  `en.json` is canonical; every other locale must define the same keys — the
  `messages.test.js` catalogue-completeness test enforces this.
- **Compiler output:** `src/paraglide/` is generated by the Vite plugin on
  every dev/build/test run and is **gitignored** — never edit it by hand.
- **Active locale** is driven from the MCP host: `App.svelte` resolves
  `HostContext.locale` (→ `navigator.language` → base) via `lib/locale.js` and
  calls Paraglide's `setLocale(tag, { reload: false })`. The `globalVariable`
  strategy (see `vite.config.js`) is required because the app runs in an iframe
  and must not navigate/reload to switch language. Locale changes pushed by the
  host (`onhostcontextchanged`) re-render the UI live.
- Only static UI chrome is localized. Photo metadata and Wally's
  `querySummary` come from source data / the assistant and are not translated.

**To add a locale:** add its tag to `locales` in `project.inlang/settings.json`,
drop a `messages/<tag>.json` with the full key set, and rebuild.
